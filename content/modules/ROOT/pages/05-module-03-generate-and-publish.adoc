= Module 3: Generate content and publish
:navtitle: 3. Generate and publish

== Learning objectives

By the end of this module, you will:

* Generate a complete workshop module using the `/showroom:create-lab` skill
* Validate content quality with `/showroom:verify-content`
* Preview your Showroom locally using Podman
* Publish your Showroom to GitHub Pages

== Time to create content

Your Showroom repository is configured and ready. Now comes the exciting part -- generating your first workshop module using AI-assisted authoring.

The `/showroom:create-lab` skill walks you through an interactive workflow that asks about your workshop topic, audience, business scenario, and learning objectives. It then generates complete, production-quality AsciiDoc files with exercises, verification steps, and proper formatting.

== Exercise 1: Generate your workshop content

. Make sure you are in your Showroom repository directory:
+
[source,role="execute"]
----
cd ~/my-first-showroom
----

. Start Claude Code:
+
[source,role="execute"]
----
claude
----

. Run the create-lab skill to generate your first module:
+
----
/showroom:create-lab content/modules/ROOT/pages/ --new
----

. The skill will ask you a series of questions. Here are suggested answers for Meridian's workshop, but feel free to customize:
+
[cols="1,2",options="header"]
|===
|Question |Suggested answer

|Workshop name
|Meridian Solutions container workshop

|Learning goal
|Learn to build and deploy containerized applications on OpenShift

|Target audience
|Developers and architects, beginner level

|Learning outcomes
|Build container images, deploy to OpenShift, configure networking and storage

|Business scenario
|Meridian Solutions needs to modernize their client delivery pipeline with containers

|Duration
|30 minutes

|Technical environment
|OpenShift (use version placeholders), single module
|===

. The skill will generate four files:
+
* `index.adoc` -- learner landing page
* `01-overview.adoc` -- business scenario and objectives
* `02-details.adoc` -- technical requirements
* `03-module-01-*.adoc` -- your first hands-on module with exercises

. When the skill finishes, exit Claude Code:
+
----
/exit
----

=== Verify

Confirm the files were generated:

[source,role="execute"]
----
ls -la content/modules/ROOT/pages/
----

You should see 4 or more `.adoc` files. Check that the navigation was updated:

[source,role="execute"]
----
cat content/modules/ROOT/nav.adoc
----

The navigation should list all generated pages.

== Exercise 2: Validate your content

The RHDP Skills Marketplace includes a verification skill that checks your content against Red Hat quality standards, AsciiDoc syntax rules, and accessibility requirements.

. Start Claude Code again:
+
[source,role="execute"]
----
claude
----

. Run the verification skill:
+
----
/showroom:verify-content
----

. Review the results. The skill checks for:
+
* Correct AsciiDoc formatting (execute blocks, list spacing, headings)
* Red Hat style guide compliance (sentence case headings, no em dashes, proper product names)
* Accessibility (alt text on images, proper heading hierarchy)
* Workshop structure (learning objectives, verification sections, learning outcomes)

. Fix any issues the verification identifies. You can ask Claude Code to fix them:
+
----
Fix the issues identified by verify-content
----

. Exit Claude Code:
+
----
/exit
----

=== Verify

Run the verification skill again to confirm all issues are resolved. A clean verification means your content is production-ready.

== Exercise 3: Preview locally

Before publishing, preview your Showroom locally to see how it will look to learners.

. From the repository root, run the Antora viewer container:
+
[source,role="execute"]
----
podman run --rm --name antora -v $PWD:/antora:z -p 8080:8080 -i -t ghcr.io/juliaaano/antora-viewer
----
+
[NOTE]
====
The `:z` suffix on the volume mount is required on SELinux-enabled systems (RHEL, Fedora). If you're on macOS, you can omit it.
====

. Open http://localhost:8080 in a new browser tab to see your rendered Showroom.

. Check that:
+
* The navigation sidebar shows all your pages
* The landing page displays your workshop title and objectives
* The module has properly formatted exercises with execute blocks
* Pagination (Next/Previous) links work between pages

. When done, press kbd:[Ctrl+C] in the terminal to stop the container.

=== Verify

Confirm the preview rendered correctly:

* Navigation sidebar shows all pages
* Content displays with proper formatting
* Execute blocks appear with the copy/run button styling

== Exercise 4: Publish to GitHub Pages

Time to make your Showroom live. The nookbag template includes a GitHub Actions workflow that automatically builds and deploys your site whenever you push to the `main` branch.

. Stage and commit your content:
+
[source,role="execute"]
----
git add -A && git commit -m "Add first workshop module"
----

. Push to GitHub:
+
[source,role="execute"]
----
git push origin main
----

. Enable GitHub Pages (one-time setup):
+
[source,role="execute"]
----
gh api repos/rhpds/my-first-showroom/pages -X POST -f build_type=workflow
----
+
[NOTE]
====
If Pages is already enabled, this command may return an error. That is fine -- it means Pages was already configured.
====

. Monitor the deployment:
+
[source,role="execute"]
----
gh run list --limit 3
----
+
Wait for the workflow to complete (typically 1-2 minutes). You can check the status with:
+
[source,role="execute"]
----
gh run list --limit 1
----

. Once the workflow succeeds, open your published Showroom:
+
link:https://rhpds.github.io/my-first-showroom/[https://rhpds.github.io/my-first-showroom/^]

=== Verify

Confirm your Showroom is live:

* The GitHub Pages URL loads successfully
* Your workshop title appears in the site header
* All modules are accessible via the navigation sidebar
* Content matches what you saw in the local preview
